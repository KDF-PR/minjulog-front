# 민주로그 프론트엔드

민주·인권·평화와 관련된 장소 여섯 곳을 방문해 사진으로 인증하고,
모은 스탬프 수에 따라 선물을 받는 모바일 웹.

| 항목 | 내용 |
| :-- | :-- |
| 프레임워크 | Angular 22 (standalone + signal) |
| 백엔드 | `kdemo-stamp-back` — Flask + Supabase, 별도 저장소 |
| 인증 | 세션 쿠키. 모든 요청에 `withCredentials` 적용 |
| 현재 상태 | 실제 백엔드 연동. mock 은 스위치 하나로 되돌아간다 |

사용자가 거치는 순서는 이렇다.

```
둘러보기 → 장소 방문 → 사진 인증 → 스탬프 적립 → 리워드 신청
```

- 둘러보기는 전부 공개다 — 메인, 방문할 곳, 장소 상세, 내 방문기록, 리워드 안내
- 로그인을 요구하는 지점은 두 곳뿐이다 — 「사진으로 방문 인증하기」와 「리워드 받기」
- 촬영 화면(`/stamp/:slug`)에 가드가 붙어 있다. 기록을 남기는 첫 지점이라
  여기서 막는다. 찍고 나서 업로드에서 401 을 만나면 헛수고가 된다
- 막힌 사람은 `/gate` 로 보내고, 원래 가려던 주소는 `returnUrl` 로 따라간다
- 헤더 오른쪽 칩이 지금 상태를 알린다 — 로그인 전에는 「로그인」, 로그인 후에는 「내 기록」
- 인증코드를 맞히면 완료 화면 없이 원래 자리로 바로 돌아간다.
  단 `returnUrl` 이 로그인·인증 화면을 가리키면 무시하고 「내 방문기록」으로 보낸다

---

## 실행

```bash
npm install
npm start        # http://localhost:4200
```

- 4200 포트가 이미 쓰이고 있으면 `npm start -- --port 4300` 처럼 지정
- lint 설정은 없다. 타입 검증은 `npm run build` 로 대신한다

### 백엔드 연결

`/api/*` 요청은 dev 프록시가 백엔드로 넘긴다 (`proxy.conf.json`).
지금 대상은 **배포된 백엔드**이므로, 로컬에서 띄운 화면도 운영 데이터를 건드린다.

주의할 점이 셋 있다.

- 로그인 화면을 열면 **실제 인증 메일이 발송된다.** 재전송 60초 제한과 발송 한도를 함께 쓴다
- 사진 인증과 리워드 신청은 서버에 그대로 남는다
- 화면만 확인할 때는 아래 mock 모드로 돌리는 편이 안전하다

로컬 백엔드(`../kdemo-stamp-back`, 포트 5001)를 쓰려면 `proxy.conf.json` 의
`target` 을 `http://localhost:5001` 로, `secure` 를 `false` 로 되돌린다.

### mock 모드

네트워크 없이 화면만으로 도는 모드다. 전환 스위치는
`src/environments/environment.ts` 의 `useMockApi` 한 곳이다.

- `true` 로 두면 로컬 fixture 로 전체 화면을 그린다. 백엔드도 프록시도 필요 없다
- mock 응답은 실제 API 의 필드명과 오류 형태를 그대로 맞춰 뒀다
- 개발 패널은 이 값이 `true` 인 개발 빌드에서만 나온다 (`app.ts` 의 `showDevTools`)

## 폴더 구조

```
src/app/
  core/          모델 · API 계약 · 도메인 서비스
  auth/          로그인 · 세션 · 라우트 가드
  pages/         화면 10개
  shared/
    layout/      헤더 · 탭바 · 구분선
    ui/          두 화면 이상이 쓰는 부품
    directives/  스크롤 등 화면 보조
    dev/         개발용 도구
```

- `core` 는 백엔드 응답 원형(`api.dto.ts`)과 화면 모델(`models.ts`), 그리고 둘을 잇는
  변환(`api.mapper.ts`)을 나눠서 보관한다. 응답 형식이 바뀌면 고칠 곳은 변환 파일 하나다
- `shared` 에는 두 화면 이상이 쓰는 것만 둔다. 한 화면 전용 컴포넌트는 그 페이지 폴더 아래에 넣는다.
  장소 상세는 이 규칙에 따라 안내 시트·내 사진 시트·방문 카드 세 개를 자기 폴더 밑에 들고 있다
- `dev` 의 개발 패널은 화면 상태를 버튼으로 오가게 해 주는 도구다.
  로그인 전 상태와 방문 0곳·3곳·6곳 시나리오를 오간다. mock 개발 빌드에서만 나온다

**HTTP 호출은 서비스 안에서만 일어난다.** 컴포넌트에는 엔드포인트도 헤더도 나오지 않는다.

### 두 화면이 같은 말을 하게 하는 곳

방문 수와 리워드 자격은 여러 화면이 같이 쓴다. 화면마다 계산하면 서로 다른 안내가 나온다.

- 남은 방문 수(`remainingToReward`)와 진행 상태(`progressState`)는 `SpaceService` 한 곳에 둔다.
  「내 방문기록」과 「참여 선물」이 이 값을 그대로 가져다 쓴다
- 필수 장소를 빼고 세 곳을 채운 경우가 특히 갈린다. 방문 수만 세면
  첫 선물이 안 열린 상태인데도 두 번째 선물을 기준으로 안내하게 된다

## 연동 API 9개

| API | 호출 시점 |
| :-- | :-- |
| `POST /api/auth/send-otp` | 인증코드 요청 |
| `POST /api/auth/verify-otp` | 6자리 입력. 성공하면 세션 쿠키 발급 |
| `GET /api/auth/user` | 로그인 상태 확인 |
| `POST /api/auth/logout` | 로그아웃 |
| `GET /api/spaces` | 장소 목록 조회 |
| `GET /api/photos` | 방문 기록 조회 |
| `POST /api/photos/upload` | 사진 인증 제출 (multipart) |
| `GET /api/rewards/eligibility` | 리워드 자격 조회 |
| `POST /api/rewards/code` | 리워드 코드 발급 |

요청과 응답의 상세한 형태는 `src/app/core/api.dto.ts` 에 있다. 각 타입 위에 대응하는
백엔드 코드 위치를 주석으로 달아 뒀다.

프론트에서 따로 처리하는 것이 둘 있다.

- **조회 3종(`spaces` · `photos` · `eligibility`)의 401 은 오류로 보지 않는다.**
  비로그인 상태로 간주하고 전부 미방문으로 표시한다. 둘러보기에서도 호출되는 API 라
  401 을 오류로 흘리면 화면이 빈 채로 멈춘다
- **사진은 올리기 전에 프론트에서 줄인다.** 긴 변을 1600px 로 맞추고 JPEG 로 다시
  인코딩해 10MB 제한 안에 들어오게 한다. 아이폰 기본 저장 형식(HEIC)도 이 과정에서 걸러진다

## 장소 데이터 구성

화면 한 장은 서버가 주는 값과 프론트가 들고 있는 값을 합쳐서 그린다.

- **서버 소유** — `id`(uuid), `name`, `is_required`. 방문 기록은 `id` 를 기준으로 연결된다
- **프론트 소유** — 주소, 소개 문구, 인증 팁, 지도 링크 같은 표시용 정보 전부.
  `src/app/core/spaces.content.ts` 에 있고, 상세 화면 본문은 `sections` 배열이 순서까지 정한다

두 값을 잇는 키는 아직 `name` 문자열이다 (`findContentByName()`).

상세 화면 본문에 넣을 수 있는 절은 다섯 종류다.

| `type` | 쓰는 필드 |
| :-- | :-- |
| `story` | `paragraphs` |
| `map` | `mapLinks` |
| `viewPoints` | `points` — 그 장소 안에서 눈여겨볼 지점 |
| `nearby` | `points` — 가까운 다른 장소 |
| `visitInfo` | `paragraphs` · `tags` |

`viewPoints` 와 `nearby` 는 목록 모양이 같아 `SpacePoint` 한 타입을 함께 쓴다.
제목과 아이콘만 다르고, 그 기본값은 화면(`SECTION_DEFAULTS`)이 종류별로 들고 있다.
`slug` 를 넣으면 그 장소 상세로 넘어가는 링크가 된다.

| 장소 | slug | 필수 |
| :-- | :-- | :--: |
| 민주화운동기념관 | `korean-democracy-museum` | ● |
| 서울시립유스호스텔 | `seoul-youth-hostel` | |
| 명동성당 | `myeongdong-cathedral` | |
| 마로니에공원 | `marronnier-park` | |
| 전태일다리 | `jeon-taeil-bridge` | |
| 광화문광장 | `gwanghwamun-square` | |

필수 표시는 리워드 1차 조건을 뜻한다. 민주화운동기념관을 포함해 세 곳을 방문해야 한다.

## 백엔드에 요청드릴 것

### 1. `spaces` 테이블에 `slug` 컬럼 추가

여섯 곳을 seed 하고 `/api/spaces` 응답에도 포함해 주시면 좋겠다.
지금은 `name` 문자열로 두 값을 잇고 있어서, 서버 쪽 장소명이 한 글자만 달라져도
그 장소가 화면에서 조용히 사라진다. slug 값과 필수 여부는 위 표를 그대로 쓰면 된다.

### 2. 대문자가 섞인 이메일로는 로그인이 안 된다

`send-otp` 는 `.strip().lower()` 로 다듬는데 `verify-otp` 는 `.strip()` 만 해서
인증코드를 찾는 키가 서로 어긋난다. 지금은 프론트에서 미리 소문자로 바꿔 우회하고 있지만,
정합을 맞추기에는 서버 쪽이 맞는 자리로 보인다.

### 3. 오류 응답에 구분 코드 추가

현재는 한국어 문장만 내려와서 상태코드로만 분기할 수 있다.
문구가 조금이라도 바뀌면 프론트 분기가 소리 없이 깨진다.

### 4. 배포 시 쿠키 설정 협의

프론트와 백엔드가 서로 다른 도메인에 올라가면 `SameSite` 조정과 `ALLOWED_ORIGINS` 추가가
필요하다. 로컬은 dev 프록시 덕분에 같은 출처라 이 문제가 재현되지 않는다.

### 5. 그 밖에

- Supabase 프로젝트가 언제쯤 준비되는지 — 연동 검증 일정을 잡으려고 한다
- 장소별 대표 이미지와 예시 인증 사진 — 지금은 목록용 썸네일로 대신 쓰고 있다
- 리워드 상품 사진 두 장 — 「참여 선물」 카드 자리를 비워 두고 기다리는 중이다

## 궁금한 점

답이 정해져야 화면을 그릴 수 있는 것들이다.

- 리워드를 신청한 **이후 상태**(검수 중 · 지급 확정 · 발송 완료)를 프론트가 알 방법이 있는지.
  구글폼으로 받는 방식이라 백엔드도 신청 상태를 모르는 구조로 이해하고 있다.
  이 때문에 화면 네 개를 만들지 못하고 세워 뒀다
- `GET /api/spaces` 를 비로그인에도 열 수 있는지. 위의 `slug` 가 오면 필요 없어진다
- 이메일로 로그인한 사람과 문자로 로그인한 사람을 **같은 사용자로 볼지**.
  지금은 `users` 에 각각 따로 쌓이는 구조로 보인다
- 운영 기간(2026-09-15 ~ 11-10)을 검사하는 쪽이 프론트인지 서버인지
- 방문을 취소하거나 사진을 지우는 API 가 필요한 상황이 있는지

## 연동 후 함께 확인할 것

백엔드를 실제로 붙이는 시점에 같이 볼 목록이다.

- 장소 목록에 여섯 곳이 다 나오는지 — `name` 매칭이 실패하면 조용히 빠지므로 개수부터 센다
- 새로고침한 뒤에도 로그인 상태가 유지되는지
- 비로그인으로 둘러볼 때 조회 3종의 401 이 오류 화면 대신 미방문 표시로 처리되는지
- 인증코드 재전송 60초 제한이 걸리는지 (429)
- 인증코드를 5회 틀리면 폐기되고 재요청 안내가 뜨는지
- 리워드 자격 판정 — 필수 장소를 포함한 세 곳과 포함하지 않은 세 곳, 두 경우 모두
- 같은 단계의 리워드 코드를 다시 요청하면 같은 코드가 오는지
- 구글폼이 설정되지 않아 `formUrl: null` 이 올 때 코드만 표시되는지
- 배포한 뒤 CORS 와 쿠키 `SameSite` — 로컬 프록시에서는 재현되지 않는다
